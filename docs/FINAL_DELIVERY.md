# Итоговый комплект КРЕСТ

Единственная итоговая ревизия указана в `REVISION.txt` архивов и PDF-отчёте.
Этот комплект включает все изменения этапов `0c5897c` и `6a934b7`, а также
последнюю проверку индикатора Telegram и инструкцию запуска.
Исторические отчёты в docs сохраняют числа своих этапов; текущие результаты
приведены в `validation/final-summary.json` и `final-python*.xml`.

## Для пользователя

Начните с [короткой русской инструкции](START_HERE_RU.md): распаковка ZIP,
запуск `start.bat`, подготовка компонентов и сохранение настроек при обновлении.
Комплект содержит исходники, **не готовый Windows-установщик**. `Setup.exe`
этой ревизии не собран и не проверен. Реальные аккаунты, микрофон, Windows-плеер
и игра здесь не тестировались. Удалённые права и интеграции не расширялись.

## Последняя проверка Telegram User

Монитор раз в секунду читает уже существующий сигнал SDK без сетевого запроса.
Установленный Pyrogram 2.0.106 использует `session.is_started`: reconnect
сбрасывает этот Event. В таком состоянии UI показывает «Переподключается».
После восстановления транспорта показывается «Связь не подтверждена».
Только успешное существующее обновление профиля подтверждает восстановление.
Если SDK не предоставляет наблюдаемый Event, статус также остаётся неизвестным.

Это ограниченная диагностика: обрыв короче секунды может не попасть между
выборками. Подтверждение восстановления может ждать штатного обновления профиля
до 300 секунд, а при FloodWait — дольше. Проверки выполнены офлайн, без аккаунта.
Состояния на скриншотах `bots-*-fixture` — явно обозначенные тестовые примеры.

## Состав

- Source ZIP: полный отслеживаемый код одной ревизии, без персональных настроек,
  моделей, токенов и локальной Python-среды.
- Review ZIP: текущий PDF и Markdown-отчёт, инструкция, контактный лист из 20
  выбранных снимков, все 29 PNG меню, JUnit и журналы, ключевые изменённые файлы.
- Patch относительно исходного `4c5be67` и git bundle для восстановления истории.
- SHA-256 и размеры готовых файлов; PDF в Library может дополнительно подписываться
  платформой, поэтому его сохранённые байты могут отличаться от локального PDF.

Никаких публикаций, развёртывания и новых запусков GitHub Actions не было.
Старый workflow не является сборкой этой ревизии.
