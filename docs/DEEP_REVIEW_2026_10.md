# Дополнительный проход: диалоги и границы доступа ботов

Этот проход продолжает ревизию `0c5897c` в той же отдельной ветке.
Публикаций, CI-запусков, новых интеграций и внешних сообщений не было.

## Архитектура и обоснование

Навыки исполняются SkillManager, команды сериализует AssistantRuntime.
Личности используют локальные авторские реплики, а не разговорную модель.
До этого прохода контекст относился преимущественно к задачам и викторине;
короткое продолжение разговора и безопасное повторение ответа отсутствовали.
Результат выполненного действия нельзя заменять случайной репликой личности.

Добавлен локальный fallback после точного сопоставления навыков:

- «ещё», «а ещё», «расскажи ещё» продолжают последнюю поддерживаемую тему
  в течение 120 секунд: факт, шутку, поддержку или варианты короткой беседы.
  Отключение разговорного модуля прекращает продолжение. Во время викторины
  неоднозначное «ещё» не меняет вопрос; явная беседа напоминает текущий вопрос.
- «повтори ответ», «повтори последний ответ», «что ты сказала» воспроизводят
  только текст недавнего локального ответа. Таймер, отправка и другое действие
  не выполняются повторно. По истечении 120 секунд выдаётся явное пояснение.
- Неизвестная и повторная неизвестная фразы получают разные полезные уточнения
  в стиле выбранной личности. Подсказки никогда не исполняются автоматически.
- Точные команды имеют приоритет. Локальные темы отделены от сценариев и
  удалённых вызовов. Формат результатов навыков, настройки и семь ключей
  личности сохранены. Это ограниченный контекст, а не свободная беседа с LLM.

## Боты и безопасность выполнения

- Telegram проверяет владельца по свежим сохранённым настройкам на каждом
  сообщении и файле. Старый ID сразу теряет доступ; отправитель должен совпасть
  с владельцем и ID личного чата. Поля owner_id в тексте/объекте сообщения
  не предоставляют доступ. Неверный/огромный ID отклоняется.
- Лимит входящей команды — 2000 символов до нормализации. Опасные команды вне
  allowlist не достигают IPC; удалённые права не расширены.
- Разрешение, блокировка компьютера и список команд повторно проверяются перед
  исполнением после очереди. Пользовательский alias не может расширить allowlist:
  изменённая итоговая команда тоже должна быть разрешена, повторной нормализации
  нет. Локальные aliases работают как прежде.
- Удалённая команда не может ответить на локальный выбор таймера или подтверждение
  игрового гида: она исполняет только явно разрешённую команду.
- Нормальное завершение Telegram/Discord SDK завершает сервис, а не запускает
  его заново. Исключения сохраняют ограниченную задержку повторного подключения.
- Steam сохраняет ошибку доставки независимо от успешной проверки API; успешная
  доставка либо отключение существующей опции снимают её. Ручное обновление
  во время cooldown сохраняется как один отложенный запрос.

## Незавершённая Telegram-авторизация

Временный marker больше не хранит телефон, API hash и phone_code_hash:
они находятся в памяти процесса. На диске только этап, PID/время запуска,
случайный идентификатор попытки и ограниченный срок. Сохранённая Telegram-сессия
не меняется. После перезапуска незавершённый запрос кода нужно начать заново.

Отмена и timeout закрывают клиент, marker и process lock. Учтена отмена в
середине Pyrogram connect до is_connected=True: закрываются session и storage.
Конкурирующая попытка и cleanup по истечении срока сериализованы. Старый файл
после аварии не блокирует мост навсегда; legacy-секреты не используются для входа.

## Проверки и ограничения

Итог: **709 passed, 3 skipped** на Python 3.12 и Python 3.13/Tk 8.6.
Все три пропуска относятся к Windows; Ruff, compileall и diff-check прошли.
Каталог остаётся из 167 навыков: новые фразы — контекст интерфейса исполнения,
а не искусственное увеличение количества зарегистрированных навыков.

Полные результаты: `validation/deep-python312.xml`, `deep-python313.xml`
и соответствующие журналы; сводка — `validation/deep-summary.json`.
Независимый ревьюер воспроизвёл обход через aliases и через локальное уточнение,
затем независимо подтвердил их устранение. Отдельные тесты проверяют реальный
Pyrogram Connect.connect с офлайн-подменой сетевой сессии.

Меню повторно открыто через настоящий Tk/ImageGrab: 27 снимков и ноль callback
errors. Два контрольных снимка и метрики сохранены в `validation/deep-menu/`.
Настоящих аккаунтов, микрофона, игры и Windows API в этом проходе не было.
Windows-установщик новой ревизии не собирался и не объявляется готовым.

Остаётся ограничение Telegram User: SDK скрывает часть reconnect-состояний;
ошибка существующего обновления bio не даёт точного online/offline-индикатора.
Новые сетевые heartbeat-запросы ради этого не добавлялись.

Library-артефакты `0c5897c` относятся к предыдущей ревизии. Этот проход не
переупаковывает и не перезагружает их ради обхода scope_violation у родителя.
