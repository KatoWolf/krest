# Windows-программа и установщик

Исходники теперь поддерживают сборку самостоятельной программы. Конечному
пользователю не нужны Python, pip или PowerShell: он запускает установщик,
затем ярлык «Крест». При первом запуске отсутствующие голосовые модели
скачиваются в фоне. Имеющиеся модели рядом с EXE или в каталоге данных
будут найдены без замены.

## Получить сборку через GitHub

1. Откройте **Actions → Windows installer → Run workflow** для выбранной проверяемой ветки.
   Первый запуск также происходит при публикации изменений Python-кода или сборочных файлов.
2. Дождитесь успешного завершения отдельных шагов компиляции, проверки ядра и
   голосовых моделей, создания установщика. Компиляция PyTorch и остальных
   компонентов тяжёлая и может занять десятки минут.
3. Внизу успешного запуска скачайте артефакт **Krest-Windows-installer**, распакуйте
   его и запустите `Krest-Setup-0.9.0.exe`.

Workflow только создаёт артефакт. Он не публикует релиз автоматически. Если шаг
сборки или проверки завершился ошибкой, готовый установщик не объявляется успешным.
Отчёт компиляции сохраняется отдельным артефактом для диагностики.

## Сборка автором на Windows

Нужны 64-битная Windows, Python 3.12, Visual Studio Build Tools с компонентом
**Desktop development with C++**, Windows SDK и Inno Setup 6. Запустите
`build-installer.bat` двойным щелчком. Это инструмент автора, а не шаг для покупателей.
Он создаст `.build-venv`, установит CPU-версию PyTorch и компоненты сборки,
скомпилирует приложение, проверит его и создаст установщик в `dist`.

Повторная компиляция использует рабочий каталог `build/windows`. Команда
`python packaging/build_windows.py --plan` показывает параметры без сборки.
`--skip-installer` оставляет проверенную standalone-папку для диагностики.
В автоматической проверке сборки запускается EXE из другой рабочей папки:
проверяются все навыки, создание дочернего ядра, локальный API, команда времени
и завершение процесса. Затем сборка скачивает модели в временный профиль,
загружает Vosk и синтезирует тестовую фразу Silero в память, без обращения к
звуковой карте. Ошибка этого шага тоже останавливает выпуск установщика.
Windows-проигрыватель и микрофон требуют отдельного
пользовательского испытания; автоматическая проверка не имитирует такое испытание.

## Что установлено и где данные

Программа: `%LOCALAPPDATA%\Programs\Krest`. Настройки, базы, модели, скриншоты и
журналы: `%LOCALAPPDATA%\Krest\Data`. Установка не требует прав администратора.
Удаление программы оставляет пользовательские данные. Перед обновлением завершите
Крест через меню, включая ядро и ботов. Для исходников по-прежнему доступен `start.bat`.

Встроенные сервисы запускаются как дочерние процессы того же EXE. Импортированные
Python-навыки и выбранные внешние скрипты остаются расширениями пользователя;
сторонние зависимости такого расширения должны входить в сборку. Установка pip
внутрь скомпилированного EXE не поддерживается. Самостоятельно редактировать
встроенные скомпилированные навыки после установки нельзя — для этого нужна новая сборка.

## О защите кода

Nuitka переводит собственные Python-модули Крест в машинный код. Установщик
содержит EXE, библиотеки и ресурсы; собственные `.py` в него не копируются.
Это затрудняет изучение исходной логики, но не делает программу неуязвимой для
дизассемблирования или исправления проверки Premium. Шифрование, ключ от которого
есть в клиенте, тоже не гарантирует секретность. Пока репозиторий публичен,
опубликованные исходники доступны независимо от способа сборки.

Приватный ключ выдачи Premium в сборку не входит; нужен только публичный ключ
проверки. Для коммерческого выпуска следует отдельно проверить лицензии выбранных
моделей и зависимостей и подписать установщик своим сертификатом издателя.
Конфигурация не содержит сертификата и не заявляет цифровую подпись от имени автора.

## Проверка перед созданием установщика

`--stage verify` сохраняет `verified-distribution.json` с SHA-256 всех файлов
standalone-каталога только после успешных проверок. `--stage installer` требует
этот манифест и отказывается работать, если файл добавлен, удалён или изменён.
После изменения каталога нужно повторить `--stage verify`. Компиляция и неудачная
повторная проверка отменяют прежнее подтверждение.

Каталог встроенных навыков EXE сравнивается с каталогом исходников по точным
идентификаторам. Большое общее число навыков не скрывает потерянные обработчики.
В диагностическом артефакте `Krest-release-diagnostics` сохраняются JSON и журналы
проверок ядра/моделей, компиляции, установщика и JUnit, включая неуспешный запуск.
Манифест подтверждает проверенные байты; он не заменяет подпись издателя.

## Бюджет и диагностика компиляции

Сборщик прерывает компиляцию через 180 минут; изменить предел можно параметром
`--compile-timeout-minutes` (1–300). Workflow отводит 190 минут шагу компиляции
и 300 минут всей задаче, чтобы оставить время для диагностики. Nuitka использует
отдельный кеш `NUITKA_CACHE_DIR`; готовая программа и квитанция verify в него не
попадают. До компиляции проверяется CPU PyTorch и сохраняется список версий.
Подробности остановленного старого запуска и ограничения — в
[BUILD_RECOVERY.md](BUILD_RECOVERY.md). Успешная сборка новой ревизии пока не получена.
